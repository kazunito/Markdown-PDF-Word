## 3. 新たに判明した実装の欠陥 — Word で章頭改ページが効かない

**`heading.pageBreakLevel` の設定が Word 出力では完全に無視されます。**

- `src/docx.ts:266-275` の `heading_open` は `new Paragraph({ heading: ... })` を作るだけで、
  改ページを一切挿入していない
- `src/docx.ts:609-` の見出しスタイル定義にも `pageBreakBefore` が無い
- Obsidian ノート `skills/Markdown-PDF変換TIL.md` §5-1 には
  「章頭改ページ = `new PageBreak()`」と**設計としては書かれている**が、実装されていない

つまり README の「章頭で改ページ ○（Word）」は誤りです。対応方針を選んでください。

| 案 | 内容 | 影響 |
|---|---|---|
| **A（推奨）** | **実装を直す。** 見出しに `pageBreakBefore` を付け、`heading.pageBreakLevel` 以下の見出しに適用する | Word 出力が PDF と揃う。README の記述は正しくなるので変更不要 |
| B | 実装は据え置き、README を「章頭で改ページ ○/—」に訂正する | 実装は変わらないが、PDF と Word の見た目が食い違ったままになる |

**A を推奨します。**「PDF と Word で同じ体裁」という要件に沿うためです。

### A を選んだ場合の変更予定（コード）

対象: `src/docx.ts` の `heading_open` の処理（266〜275 行）

```
変更前
  out.push(new Paragraph({
    heading: HEADING_LEVELS[Math.min(level, 6) - 1],
    children: inlineToRuns(inline, cfg),
  }));

変更後
  out.push(new Paragraph({
    heading: HEADING_LEVELS[Math.min(level, 6) - 1],
    // PDF 側の pageBreakCss と同じ基準で、設定した階層までの見出しの前で改ページする
    pageBreakBefore: level <= cfg.heading.pageBreakLevel,
    children: inlineToRuns(inline, cfg),
  }));
```

※ 本文の先頭見出しにも改ページが入ると白紙ページが出ます。実装時は
「本文セクションの最初の見出しでは改ページしない」判定を入れ、変換して実測で確認します。
確認は Word 実機で PDF 化して行います（手順は `skills/Markdown-PDF変換TIL.md` §5-4）。
