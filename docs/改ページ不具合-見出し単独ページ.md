# 見出しだけのページができる不具合の修正記録

- 日付: 2026-08-08
- 対象: Markdown-PDF-Word 拡張（PDF 出力）
- 症状: 見出し（例「13.2 実装済み又は実装定義済みの主な統制」）だけが 1 ページを占め、
  直下にあるはずの表が次のページへ送られる

---

## 1. 原因

`src/template.ts` の印刷用 CSS で、`table` に `break-inside: avoid`（＝途中で分割するな）を
指定していたことが原因です。

```css
/* 修正前 (src/template.ts:157) */
table, pre, img, figure, blockquote { break-inside: avoid; }
```

Paged.js（改ページを組む部品）は `break-inside: avoid` の要素が現在のページに入りきらないとき、
次の順で処理します。

1. **まず表全体を次のページへ丸ごと移動する**
2. 移動先のページでもなお溢れる場合に**限って**、表を分割する

見出しには `h1, h2, h3 { break-after: avoid; }`（＝見出しの直後で改ページするな）を指定して
いますが、これは「見出しを表に追随させる」指定ではありません。表だけが次ページへ移動した結果、
**見出しだけが取り残されたページ**ができます。

実際に報告された 43 ページの文書では、12.2（p22 に見出しのみ・表は p23〜25）と
13.2（p32 に見出しのみ・表は p33）が同じ原因でした。

---

## 2. 修正内容

ファイル: `src/template.ts`（157〜162 行目）

### 修正前

```css
table, pre, img, figure, blockquote { break-inside: avoid; }
```

### 修正後

```css
pre, img, figure, blockquote { break-inside: avoid; }
/* 表に break-inside: avoid を付けると表全体が次ページへ移動し、見出しだけが残る。
   表はページ境界で分割してよいものとし、行の途中では切らない */
tr, th, td { break-inside: avoid; }
/* 続きのページにも見出し行を出す指定。Paged.js 0.4.3 は未対応で現状は効かない
   (Word 出力は docx 側の tableHeader で繰り返される) */
thead { display: table-header-group; }
```

意図:

| 指定 | 意味 |
|---|---|
| `table` を対象から外す | 長い表はページ境界で自然に分割してよい、とする |
| `tr, th, td` に `break-inside: avoid` | 1 行の途中（文字の高さの半ばなど）では切らない |
| `thead { display: table-header-group; }` | 続きのページにも表の見出し行を出す指定（後述のとおり現状は無効） |

1 ページに収まる小さい表は、修正後も分割されません。

## 4. 未解決として残した点

**分割された表の 2 ページ目以降に、ヘッダ行（見出し行）が繰り返されません。**

`thead { display: table-header-group; }` は CSS 標準として正しい書き方ですが、
本拡張が使っている **Paged.js 0.4.3 が未対応**のため無視されます。
実際に p4・p5 には「備考」（ヘッダ行のセル）が出現しないことを確認済みです。

```bash
# 目的: 表のヘッダ行が各ページに出ているかをページ単位で数える
#       '備考' はテスト用の表のヘッダ行にだけ現れる語。これを目印にする
#       for p in 3 4 5 は「3・4・5 ページ目について順に調べる」の意味
#       grep -c は一致行数を数える指定なので、1 なら出ている / 0 なら出ていない
for p in 3 4 5; do echo -n "p$p: "; pdftotext -f $p -l $p break-test.pdf - | grep -c '備考'; done
# → 実測は「p3: 1 / p4: 0 / p5: 0」。表が始まる p3 にしかヘッダ行が無い
# → 期待する姿は「p3: 1 / p4: 1 / p5: 1」。これが未解決の制限（Paged.js 0.4.3 が未対応）
```

対応するには、`pagedjs-cli` の `additionalScripts` オプション
（`node_modules/pagedjs-cli/src/printer.js:180` で、Paged.js 本体の後に読み込まれる）から
`Paged.registerHandlers` を注入し、継続ページ側の表に `thead` を複製する処理が必要です。

今回のご依頼（見出し単独ページの解消）の範囲外のため、**着手していません**。

なお **Word（.docx）出力側は既にヘッダ行が繰り返されます**。
`src/docx.ts:225` の `new TableRow({ children: cells, tableHeader: isHeader })` が
その指定にあたります。

## 7. 第 2 の事例: 長いコードブロックでページの下半分が空く（0.2.1 で修正）

### 7-1. 症状

`5.1 置き場所` の見出しと本文 1 段落だけが表示され、**ページの残り 3/4 が白紙**になる。
続きのページに `buildspec.yml` のコードブロックが現れる。

### 7-2. 原因

§1 と同型。`table` は対象から外したが、**`pre`（コードブロック）と `blockquote`（引用）に
`break-inside: avoid` が残っていた**。1 ページに収まらない要素は丸ごと次ページへ送られる。

```css
/* 修正前 src/template.ts */
pre, img, figure, blockquote { break-inside: avoid; }
```

### 7-3. 修正内容

```css
/* 修正後 src/template.ts。分割できない img / figure だけを対象に残す */
img, figure { break-inside: avoid; }
pre, blockquote { break-inside: auto; orphans: 2; widows: 2; }
```

Word 側は 1 段落として出力しており既定で分割されるため、コードブロックの問題は無かった。
一方で**見出しに `keepNext` が無く**、PDF 側の `h1, h2, h3 { break-after: avoid }` に
相当する指定が欠けていたため、併せて `src/docx.ts` の見出し段落に追加した。

```ts
// src/docx.ts の heading_open
keepNext: true,   // 見出しを次の段落と同じページに保つ
keepLines: true,  // 見出し自体を途中で分割しない
```

### 7-4. 検証結果（PDF・Word の両方を実測）

検証文書 `verify/doc-pre.md`（長いコードブロック 60 行 + 引用 20 行 + 表 40 行）。

| 経路 | 修正前 | 修正後 |
|---|---|---|
| PDF（Paged.js） | 6 ページ。見出しのあるページは **4 行**しか埋まらない | 5 ページ。同じページが **38 行** |
| PDF（全ブロック入りの拡張版） | — | 8 ページ。本文各ページ **37〜39 行** |
| Word（実機で PDF 化） | 8 ページ。空きページは無し（元から正常） | 8 ページ。**28〜35 行**。見出しが単独で残らない |

```bash
# 目的: 変換して各ページに何行入ったかを数える。行数が極端に少ないページ＝空きが出ているページ
npx tsc -p .                                              # CSS は TypeScript 内にあるので必ず再コンパイルする
MF_PROTECTION=none node verify/run-local.js verify/doc-pre.md
# → 「PDF : /.../verify/out/doc-pre.pdf」と出れば成功
cd verify/out
for p in $(seq 1 $(pdfinfo doc-pre.pdf | awk '/^Pages/{print $2}')); do
  echo "p$p: $(pdftotext -f $p -l $p -layout doc-pre.pdf - | sed '/^[[:space:]]*$/d' | wc -l) 行"
done
# → 本文ページが 30 行前後で揃っていれば正常
# → 1 桁の行数のページがあれば、そのページで要素が丸ごと次へ送られている

# 目的: Word 側の見出しに keepNext が入ったか数える（見出しの数と一致すること）
unzip -p doc-pre.docx word/document.xml | grep -o 'keepNext' | wc -l
# → Markdown の見出し数（grep -c '^#' の値）と同じであること
```

### 7-5. 教訓

`break-inside: avoid` は「**そのページに入りきる要素**」にだけ付けてよい。
1 ページを超えうる要素（表・コードブロック・引用）に付けると、必ず空きページを生む。
分割できない `img` / `figure` だけが対象として妥当。
