# 多言語化（英語を既定・日本語を上書き）計画

- 日付: 2026-08-08
- 対象: Markdown-PDF-Word 拡張 v0.1.0 → v0.2.0
- 背景: 利用者 30 人のうち日本語を読むのは 2 人。リポジトリも公開済み。
  現状は画面表示・設定説明・リリースノートがすべて日本語のみで、28 人が読めない。

---

## 1. 方針

VSCode の慣例どおり、**既定（フォールバック）を英語**とし、**日本語を上書き**として置く。
表示言語が日本語なら日本語、それ以外なら英語が出る。日本語版の読み込みに失敗しても
英語にフォールバックするため、誰も読めない状態にはならない。

| 層 | 対象 | 仕組み |
|---|---|---|
| マニフェスト | 設定説明・コマンド名・分類タイトル・拡張説明 | `package.json` の文字列を `%key%` に置換し、`package.nls.json`（英語）と `package.nls.ja.json`（日本語）を置く |
| 実行時 | 通知・エラー・入力欄・ログ | `vscode.l10n.t()` に置換し、`l10n/bundle.l10n.ja.json` を置く。`package.json` に `"l10n": "./l10n"` を追加 |
| 配布物 | リリースノート | 英語を先に、日本語を後に併記する |

## 3. 作業手順

### 段階 1: マニフェストの多言語化

1. `package.json` の対象 61 箇所を `%markdownFormal.xxx%` 形式のキーに置換する
2. `package.nls.json`（英語）を作成する
3. `package.nls.ja.json`（日本語。現在の文言をそのまま移す）を作成する
4. **キーの過不足を機械照合する**（後述の検証 1）

キー命名規則: `<設定キー>.description` / `<設定キー>.enum.<値>` /
`configuration.<分類 id>.title` / `command.<コマンド id>.title` / `submenu.label` / `description`

### 段階 2: 実行時文言の多言語化

1. `package.json` に `"l10n": "./l10n"` を追加する
2. `src/*.ts` の対象 46 箇所を `vscode.l10n.t('<英語原文>')` に置換する
   （`vscode.l10n.t()` は**英語原文をキーとして使う**ため、英語を直接書く）
3. `l10n/bundle.l10n.ja.json` に「英語原文 → 日本語」の対応を書く
4. 変数を含む文言は `vscode.l10n.t('Exported: {0}', path)` の形にする

### 段階 3: 既定値の見直し

`src/config.ts` の 2 箇所と、対応する `package.json` の `default` を英語に変更する。

### 段階 4: 文書の更新

| ファイル | 更新内容 |
|---|---|
| `README.md` | 表示言語の切り替え方、日本語で文書を作る場合の設定（`toc.title` 等）を追記 |
| `README.ja.md` | 同上（日本語版） |
| `docs/運用手順.md` | 既定値が英語になった旨を反映 |

### 段階 5: リリース

1. `package.json` の版数を `0.2.0` に上げる
2. `npm run compile` → `npx --yes @vscode/vsce package`
3. `code --install-extension ... --force`
4. **v0.1.0 のリリースノートを英日併記に更新する**（既に公開済みのため差し替え）
5. v0.2.0 のリリースを英日併記で作成し、VSIX を添付する

## 4. 検証

### 検証 1: キーの過不足（観点 A＝差分）

```bash
# 目的: package.json が参照するキーと、翻訳ファイルのキーが完全に一致するか調べる
#       ここがズレると、設定画面に %markdownFormal.xxx% という生のキーが表示される
cd /Users/nito/Code/Markdown-PDF-Word
node -e "
const fs=require('fs');
const raw=fs.readFileSync('package.json','utf8');
const used=[...new Set([...raw.matchAll(/%([A-Za-z0-9_.]+)%/g)].map(m=>m[1]))];
for (const f of ['package.nls.json','package.nls.ja.json']) {
  const keys=Object.keys(JSON.parse(fs.readFileSync(f,'utf8')));
  console.log(f, '未定義:', used.filter(k=>!keys.includes(k)), '余分:', keys.filter(k=>!used.includes(k)));
}"
# → 両方とも「未定義: [] 余分: []」であること
# → 1 つでも残っていれば、その場で翻訳ファイルに追記してから次へ進む
```

### 検証 2: 実行時文言の対応漏れ（観点 A）

```bash
# 目的: l10n.t() に渡した英語原文が、日本語バンドルに漏れなく載っているか調べる
node -e "
const fs=require('fs');
const src=fs.readdirSync('src').filter(f=>f.endsWith('.ts'))
  .map(f=>fs.readFileSync('src/'+f,'utf8')).join('\n');
const used=[...new Set([...src.matchAll(/l10n\.t\(\s*'((?:[^'\\\\]|\\\\.)*)'/g)].map(m=>m[1]))];
const ja=Object.keys(JSON.parse(fs.readFileSync('l10n/bundle.l10n.ja.json','utf8')));
console.log('日本語訳が無い:', used.filter(k=>!ja.includes(k)));
console.log('使われていない訳:', ja.filter(k=>!used.includes(k)));"
# → 両方とも [] であること
# → 「日本語訳が無い」に残ると、日本語環境でもそこだけ英語で表示される
```

### 検証 3: 日本語リテラルの残存（観点 B＝独立した根拠源）

```bash
# 目的: 画面に出る日本語が src/ に直接書かれたまま残っていないか、別の切り口で調べる
#       コメント行（// や * で始まる行）は対象外なので除外する
grep -nE "'[^']*[ぁ-んァ-ヶ一-龥][^']*'" src/*.ts | grep -vE ':[0-9]+: *(//|\*|/\*)'
# → 何も出力されないこと
# → 出力された行は l10n.t() への置換漏れ。1 行ずつ潰す
```

### 検証 4: 実機での表示確認（観点 B）

```bash
# 目的: 実際に VSCode の表示言語を切り替えて、英語・日本語の両方が正しく出るか目で確認する
code --install-extension markdown-formal-pdf-0.2.0.vsix --force
# → VSCode を再読み込み後、コマンドパレットで「表示言語を構成する」を実行し en に切り替える
# → 設定画面 (@ext:kazunito.markdown-formal-pdf) の説明が英語になっていれば成功
# → %markdownFormal.xxx% のような生のキーが見えたら失敗。検証 1 に戻る
# → ja に戻して、日本語で表示されることも確認する
```

### 検証 5: 変換結果の非退行

```bash
# 目的: 多言語化で変換処理を壊していないことを確認する
node verify/run-local.js verify/doc3.md
# → 「PDF :」「Word:」の 2 行が出れば成功
pdfinfo verify/out/doc3.pdf | grep Pages
# → 多言語化の前後でページ数が変わらないこと
```

---

## 5. 実施しないこと

| 項目 | 理由 |
|---|---|
| 英語・日本語以外の言語 | 利用者の言語構成が未確認。追加は `package.nls.<locale>.json` を置くだけで済む |
| 出力文書そのものの翻訳 | 文書の言語は利用者が Markdown で決める。拡張が介入する領域ではない |
| `docs/*.md` の英訳 | 分量が大きく、UI の多言語化とは独立して実施できる。別作業とする |

---

## 6. 想定される失敗

| 失敗 | 兆候 | 対処 |
|---|---|---|
| キーの綴り誤り | 設定画面に `%markdownFormal.xxx%` と表示される | 検証 1 で事前に検出する |
| `l10n` の宣言漏れ | 日本語環境でも英語のまま表示される | `package.json` の `"l10n": "./l10n"` を確認する |
| `{0}` の書き換え漏れ | 文中に `{0}` がそのまま表示される | 検証 4 の実機確認で発見する |
| 既定値変更による驚き | 日本語文書の目次見出しが `Contents` になる | README に設定での戻し方を明記する |
